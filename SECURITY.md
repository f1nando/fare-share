# Security Policy

Fare Share is under active development. The public environment currently uses a
disposable Solana mainnet rehearsal deployment and test-branded assets; it is not
the final production release.

## Reporting a vulnerability

Please report suspected vulnerabilities privately to:

**Ivan Dalechenko, CTO**

- [ivandalechenko@gmail.com](mailto:ivandalechenko@gmail.com)
- [Telegram: @ivandalechenko](https://t.me/ivandalechenko)

Include, when possible:

- the affected URL, program instruction, account, or commit;
- a clear reproduction sequence;
- expected and observed behavior;
- impact and any known preconditions;
- relevant transaction signatures without private keys or secrets.

Do not publish an unresolved vulnerability in a GitHub issue or social-media
post. Never send seed phrases, private keys, authentication cookies, API keys,
keypair files, or unredacted server configuration.

## Scope

Reports are particularly useful for:

- unauthorized movement or accounting of protocol-controlled assets;
- bypasses of NFT ownership, collection, mint, signer, or canonical ATA checks;
- replay or substitution of mint quotes, trainee vouchers, or swap plans;
- unsafe Jupiter route validation or transaction mutation;
- incorrect reward, claim, repair, expiry, pause, or rescue behavior;
- admin authentication, CSRF, origin, rate-limit, or secret-exposure issues;
- mismatches between the transaction shown to a wallet and the submitted bytes.

The procedural city, visual defects, unavailable third-party routes, test-token
market volatility, and issues already documented as rehearsal limitations are
normally not security vulnerabilities unless they create a concrete loss or
authorization bypass.

## Safe research expectations

- Use your own wallet and funds.
- Minimize transaction value and avoid disrupting other users.
- Do not access, modify, or retain another user's data.
- Do not perform denial-of-service, spam, social engineering, or credential
  attacks.
- Stop testing and contact us if you encounter private data or a credible risk
  of asset loss.

There is currently no formal bug-bounty program or guaranteed reward. We will
acknowledge good-faith reports and coordinate validation and remediation.
