# Эталон города: хорошая производительность, v1

Пользователь одобрил текущий вариант 21 сентября 2026 года как отличный по производительности. Сохраняем его как точку возврата перед следующими экспериментами.

**Git-тег: `city-perf-good-v1`.** Тег локальный, аннотированный; не перемещать его при следующих изменениях. Новую одобренную версию сохранять отдельным тегом. Последнее изменение кода города в этом эталоне — `a468def`; последующие на момент фиксации коммиты касались других документов, код frontend совпадает.

В эталоне есть:

- React / Three.js, простой серый город и яркие жёлтые такси;
- Worker с симуляцией 30 Гц, запасом состояний около 200 мс и плавной интерполяцией;
- ограниченная область симуляции, instancing и прежние оптимизации трафика;
- двойные парки, Т-перекрёстки и маршрутизация по открытым улицам;
- ускоренная на 50% камера; сохранены обгоны, повороты, крены, прыжки, фары и визуальные гудки.

Настройки по умолчанию: машины 70%, такси 7%, поток 130%, скорость такси 120%, лихачество 10%, квартал 40, приближение 80%, камера 200%, палитра `pale`. Дополнительный коэффициент скорости камеры 1,5 уже включён в код. Настройки браузера хранятся отдельно в localStorage и Git-тегом не восстанавливаются; для воспроизводимого сравнения использовать фиксированный сценарий стенда.

## Основание и границы измерений

Android, Chrome 152, 393 × 736, DPR 1,6, сценарий main, 60 секунд: после переноса симуляции в Worker FPS вырос с 52,7 до 58,2; CPU рендер-цикла снизился с 13,445 до 2,905 мс; кадр p95 — с 33,4 до 16,8 мс. Запас состояний — 125,777 мс в среднем, минимум 49,9 мс, исчерпаний 0. Приём сообщений вне рендер-цикла — ещё 0,15 мс в среднем на кадр. GPU-таймер недоступен. Отчёт: `taxi-performance-mub5mwih-gfjpul.json`.

Этот мобильный отчёт относится к версии с Worker **до добавления парков и ускорения камеры**. Текущий вариант с парками дополнительно проверен на ПК: 20 секунд, запас 126,993 мс, исчерпаний 0; короткое чередующееся Node-сравнение не показало существенного роста стоимости шага. Числа Android не выдаются за отдельный замер текущей планировки. Подробности — [журнал измерений](OPTIMIZATION-RESULTS.md).

## Быстро открыть сохранённый вариант

Из корня основного репозитория в PowerShell:

```powershell
git worktree add --detach ..\taxi-performance-good city-perf-good-v1
cd ..\taxi-performance-good
npm ci
npm run build
npm run preview -- --host 0.0.0.0 --port 4175 --strictPort
```

Это отдельная копия эталона: текущая разработка и её незакоммиченные изменения остаются на месте. Если каталог уже создан, перейти в него и повторно использовать его. Просмотр с другого устройства: `http://<IPv4 компьютера>:4175/`; для измерения добавить `?benchmark=1&duration=60`. Доступ с телефона зависит от существующих правил локальной сети/брандмауэра.

Для возврата основной разработки к эталону использовать этот тег как источник изменений города, сохранив текущую работу и создав отдельный commit отката. Не откатывать целиком историю репозитория: в ней есть независимые изменения других частей проекта. Запрос «верни эталон производительности v1» означает именно эту сохранённую версию города.
